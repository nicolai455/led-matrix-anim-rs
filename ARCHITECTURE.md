# Rust rewrite integration contract

Preserve the existing Arduino tree and all pre-existing uncommitted edits. New implementation lives in `rust/`; no commits, pushes, hardware flashing or credential reads. Target real ESP32-WROOM (including bare/no mic) and ESP32-S3 N16R8; host simulator is an additional test surface, not a replacement for firmware.

Workspace crates:
- `matrix-core`: pixel/frame, geometry/panel configuration, audio analysis, parameter descriptors, Effect trait, Engine/config/state/commands, frame-file parsing.
- `matrix-effects`: every existing effect, one module per effect/family, public `builtin_effects() -> Vec<Box<dyn matrix_core::Effect>>`.
- `matrix-control`: shared bounded-command render actor/control hub, Home Assistant discovery generation, web UI asset, host HTTP/MQTT adapters and simulator binary. ESP32 networking adapters use the same hub and discovery.
- `matrix-firmware`: ESP-IDF std firmware, standalone excluded from host workspace if needed, hardware adapters and ESP32/S3 build profiles. Uses all three libraries without host-network dependencies.

## Fixed public core API (coordinate any unavoidable changes explicitly)

`pub const WIDTH: usize = 32; pub const HEIGHT: usize = 32; pub const PIXELS: usize = 1024;`
`#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, Serialize, Deserialize)] pub struct Rgb { pub r:u8, pub g:u8, pub b:u8 }`, with `new`, `BLACK`, `WHITE`, `hsv(h:f32,s:f32,v:f32) -> Self` (hue in 0..1), `scale(self, factor:f32) -> Self`.
`pub struct Frame { pub pixels: [Rgb; PIXELS] }`, Clone, Default, `clear(Rgb)`, `set(x:usize,y:usize,Rgb)`, `get(x:usize,y:usize)->Rgb`; row-major logical pixels; out-of-range writes no-op.
`#[derive(Clone, Debug)] pub struct AudioSnapshot { pub bands:[f32;16], pub waveform:[f32;128], pub level:f32, pub peak:f32, pub beat:bool, pub available:bool }`, Default, normalized finite values.
`pub struct RenderContext<'a> { pub now_ms:u64, pub delta_seconds:f32, pub audio:&'a AudioSnapshot, pub color:Rgb, pub text:&'a str, pub scroll_speed:f32 }`.
`#[derive(Clone, Copy, Debug, Serialize)] #[serde(rename_all="snake_case")] pub enum ParameterKind { Number, Boolean, Select }`
`#[derive(Clone, Debug, Serialize)] pub struct ParameterDescriptor { pub id:&'static str, pub label:&'static str, pub kind:ParameterKind, pub min:f32, pub max:f32, pub step:f32, pub default:f32, pub options:&'static [&'static str], pub unit:&'static str }`.
`pub trait Effect: Send { fn id(&self)->&'static str; fn name(&self)->&'static str; fn parameters(&self)->&[ParameterDescriptor] { &[] }; fn parameter(&self,id:&str)->Option<f32> { None }; fn set_parameter(&mut self,id:&str,value:f32)->Result<(),String>; fn reset(&mut self) {} fn render(&mut self,frame:&mut Frame,context:&RenderContext<'_>); }`. Effects without parameters return Err from set_parameter.
`pub struct Engine`; `Engine::new(effects:Vec<Box<dyn Effect>>) -> Result<Self,String>`; `apply(&mut self, kind:&str, payload:&str)->Result<(),String>` (legacy MQTT kinds, with atomic validation); `render(&mut self, now_ms:u64, audio:&AudioSnapshot)->Frame`; `snapshot(&self)->serde_json::Value`; `catalog(&self)->serde_json::Value`. Catalog is array of `{id,name,parameters:[{id,label,kind,min,max,step,default,options,unit,value}]}`. Snapshot preserves legacy `{state:"OFF|ON",brightness,color:{r,g,b},color_mode:"rgb",effect:<display name>,effect_id,text,speed,cycle:"ON|OFF",audio_source:"Off|Synthetic|Mic",audio_status,effects:{id:{param:value}},...}`. Engine boots OFF; frames returned by render are logical full brightness (output applies snapshot brightness/power/current limit). `Engine::is_on()->bool`; `Engine::brightness()->u8`. Core provides `pub fn synthetic_audio(now_ms:u64)->AudioSnapshot` and actual PCM DSP for microphone adapter.
Frame playback is an effect named `Frames`, with core parser for existing frames.json format; effects crate exposes a public constructor so platform code can load an asset file. Port actual existing frames format; do not assume it.

## Fixed control API
`pub trait LedOutput: Send + 'static { fn show(&mut self,frame:&Frame,brightness:u8)->Result<(),String>; }`.
`pub trait AudioInput: Send + 'static { fn snapshot(&mut self, now_ms:u64)->AudioSnapshot; }`.
`#[derive(Clone)] pub struct ControlHub`.
`ControlHub::spawn(engine:Engine, output:impl LedOutput, audio:Option<Box<dyn AudioInput>>) -> Result<Self,String>` starts a dedicated render thread. No target FPS/fixed frame interval: physical blocking output is frame backpressure; simulator implements wire-equivalent pacing in its sink, not the render engine. Yield each iteration for scheduling fairness. All mutable Engine access stays on render thread; bounded commands applied in finite batches; network threads use nonblocking submission; snapshots and preview are cached and refreshed at bounded cadence, never hold a state lock across render/show/network I/O. Enforce backpressure. API `submit(&self,kind:&str,payload:&str)->Result<(),String>`, `snapshot(&self)->serde_json::Value`, `catalog(&self)->serde_json::Value`, `frame(&self)->Frame`. Add clean shutdown handle as appropriate.
`pub fn discovery(device_id:&str, catalog:&serde_json::Value)->Vec<(String,String)>` in matrix-control: legacy topics `homeassistant/<domain>/<device_id>/<entity>/config`, base `ledmatrix/<device_id>`, availability, light+text+speed+cycle+rssi+audio+all effect parameters. Retained discovery/state; last will offline; HA online and reconnect cause rediscovery and current state publication. Both platforms consume same function.
UI embedded as `pub const WEB_UI:&str` and same HTTP/API on host and firmware where practical: GET `/`, `/api/state`, `/api/effects`, `/api/frame`; POST `/api/command` with `{kind,payload}` (payload object or string) returning queue acceptance/validation failure; legacy endpoint compatibility where feasible. Must show effect selection, power/brightness/RGB/text/scroll/cycle, generated parameters, audio controls, live FPS/status, preview. Persist settings and expose panel/power/mic configuration; firmware should support OTA and assets, and document genuine limitations instead of empty routes.
Host features gated `host`; matrix-control default can be host, firmware uses `default-features=false`. Host binary `matrix-simulator` supports `--listen`, optional network config (never read existing real network.json), configurable device-id and asset/state paths; no credentials in logs. Depend on existing UI only for read-only reference, not old Arduino runtime.

## Responsibility boundaries
Core worker owns `rust/crates/matrix-core/**` and root workspace Cargo.toml/Cargo.lock. Effects worker owns `rust/crates/matrix-effects/**`. Control worker owns `rust/crates/matrix-control/**`. Firmware worker owns `rust/firmware/**` (package matrix-firmware), platform build scripts/config under that directory, and firmware docs. Parent owns integration tests, top-level docs, and review. Workers may read all code; edit only owned paths. Do not run `cargo fmt --all` until all workers finish (format your own files only). Root workspace members core/effects/control, exclude firmware. Cargo dependencies should use published, verified APIs. Prefer ESP-IDF esp-idf-svc/hal/sys for both Xtensa devices, RMT WS2812, I2S mic, Wi-Fi, NVS, HTTP, MQTT, OTA. Parallel pins must genuinely output all four panels; do not silently treat parallel mode as a single chain. Verify SDK GPIO validity, including original S3 GPIO46 restriction, rather than blindly preserving an invalid pin.

## Acceptance
Real host tests and simulator HTTP/MQTT exercised; cross-build ESP32 and ESP32-S3 (or clearly report actual toolchain/network blocker after attempting). Every legacy registered effect accounted for and tested at variable dt/audio. Stable IDs/labels/parameter ranges traced from source. No placeholder effects, fake mic data in Mic mode, fake OTA success, or unimplemented feature claims. Keep firmware boot dark and power current limiter. Never use/test with actual user's network credentials or flash attached hardware. Report exact tests and any feature gaps for parent review.
